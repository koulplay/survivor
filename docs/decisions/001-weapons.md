# 001. Оружие — наследники интерфейса `Weapon`

**Статус:** принято 28.10.2026 (коммит «Move pistol and aura behind Weapon interface», ветка `c3-weapon`); проверено 29.10.2026 — третье оружие, клинки, добавлено новым классом и строкой в списке.
**Шаг:** C3. Запись — Claude по твоим причинам; ты проверяешь, что причины твои (`docs/roadmap.md`, «Принципы», «Решения записываем»).

## Контекст

До C3 пистолет и аура были разложены по всему коду: поля в `Player`, свои функции в `update.cpp`, ветки в `UpdatePlayerDamage`, строки в `Draw`, поля в хэш-тесте (урок C3, раздел 1). Третье оружие тем же способом — ещё одна порция правок в тех же файлах, и компилятор не напомнил бы ни об одной.

По плану оружий станет больше: уровни (C5), эволюция, которая заменяет одно оружие другим (C8). Операций у любого оружия мало, и они одни и те же: обновиться за тик и нарисоваться.

Рассматривали три пути:

| Путь | Новое оружие — это | Цена |
|---|---|---|
| как было: поля и функции на каждое оружие | правки `Player`, `update.cpp`, `draw.cpp`, хэша | компилятор не подскажет забытое место |
| `std::variant<Pistol, Aura, Blades>` и `std::visit` | новый тип в списке `variant` и ветка в каждом `visit` | набор типов закрыт; зато ни кучи, ни виртуального вызова, и забытую ветку ловит компилятор: обработчик должен быть «a Callable that accepts every possible alternative from the variant» (cppreference, `std::visit`), без ветки для `Blades` — ошибка компиляции (прогон Claude 31.10.2026, GCC 13.3) |
| абстрактный класс `Weapon` и наследники | новый класс и строка в `StartingWeapons` | каждый объект — отдельно в куче, вызов — через таблицу виртуальных функций |

Сравнить `variant` вживую должен был шаг C4. Его убрали 28.10.2026 — твоими словами: «Просто мне кажется C4 будет лишним. А так главное в целом базу middle разработчика». Сравнение `variant` и наследования перенесено в F4, на события.

## Решение

- `class Weapon` — договор из двух чисто виртуальных функций, `Update(World&, float dt)` и `Draw(const World&) const`, и виртуального деструктора (C++ Core Guidelines, C.35: «A base class destructor should be either public and virtual, or protected and non-virtual»).
- `Pistol`, `Aura`, `Blades` — наследники; всё о каждом оружии, его состояние и правила, — в его классе. Пули живут внутри `Pistol`.
- Список — `std::vector<std::unique_ptr<Weapon>> weapons` в `Player`, начальный набор даёт `StartingWeapons()` (`world.h`, 99; `weapon.cpp`, 146–152). `unique_ptr` — потому что список владеет оружием (Core Guidelines, R.20: «Use `unique_ptr` or `shared_ptr` to represent ownership»), а наследников разного размера в одном векторе по значению не сложить — была бы срезка (урок C3, 4.4).
- Цикл знает только «обнови всех» и «нарисуй всех» (`update.cpp`, 259; `draw.cpp`, 72) — паттерн Update Method (Game Programming Patterns, «Update Method»).
- Общая для оружий логика таймера — класс `Cooldown` в `weapon.h` (с 30.10.2026).

Почему наследование, а не `variant`: в этой игре растёт набор типов (новые оружия), а не набор операций над ними. Для закрытого набора типов с данными без поведения план выбирает `variant` — события в F4.

## Последствия

Хорошее:
- Новое оружие — новый класс и строка в `StartingWeapons`: так добавлены клинки 29.10.2026, циклы в `update.cpp` и `draw.cpp` не тронуты.
- Правила каждого оружия проверяются тестом через его открытые функции, без общего `Update` (`tests.cpp`, тесты `[weapon]`).

Цена:
- `World` и `Player` стали только перемещаемыми. Рестарт `w = World(43)` компилируется — это перемещение; любая копия мира — ошибка компиляции из глубины стандартной библиотеки. При этом `std::is_copy_constructible_v<World>` отвечает `true` (прогон Claude 31.10.2026, GCC 16.2), так что трейту здесь верить нельзя (урок C3, 2.5 и 5.7).
- Нужен виртуальный деструктор, а `-Wall -Wextra -Wpedantic` его отсутствие не ловят — в флагах `-Wnon-virtual-dtor` (`CMakeLists.txt`).
- Каждое оружие — отдельное выделение памяти, каждый вызов — через таблицу виртуальных функций. На трёх оружиях не замерялось; замеры — этап E.
- Порядок в списке — порядок ударов в тике: пистолет, аура, клинки. От него зависит, кто добивает врага.
- Тест `[hash]` видит оружие только через мир: в хэше лишь `player.weapons.size()` (`tests.cpp`, 43); расхождение внутри оружия заметно, только когда оно изменило мир (урок C3, 3.4, вопрос 6).
- Улучшения пистолета (`bullet_speed_upgrade`, `bullet_fire_interval_upgrade`) живут в `Player`, то есть часть пистолета — вне его класса. Улучшения перестроят шаги C5–C7.
- Тестам нужны открытые константы и функции наблюдения: `kFireInterval`, `kSpawnInterval`, `kCircleRadius`, `GetBullets()`, `IsActive()`.

Пересмотреть:
- F4 — события через `variant`: дописать сравнение с этим решением в `004-events.md`.
- C8 — эволюция меняет список оружий: менять его после цикла «обнови всех», не изнутри `Update` оружия (урок C3, 5.9).
